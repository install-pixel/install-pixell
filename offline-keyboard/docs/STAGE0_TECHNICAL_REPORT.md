# Етап 0 — технічний звіт

Дата: 2026-10-21. Статус: **попередній**. Розділи про Android API ґрунтуються на документації й
реалізованому коді. Розміри, швидкість і якість моделей ще **не виміряні** на цільовому телефоні:
у середовищі розробки не було ні пристрою, ні доступу до сайтів моделей (alphacephei.com, huggingface.co).
Позначка ⚠ означає дані, які треба перевірити до інтеграції.

## 2. Версії Android

- **minSdk 26 (Android 8.0).** Адаптивні іконки, сучасні API `InputMethodService`; охоплює практично всі
  робочі телефони. Нижче опускатися немає потреби, а локальні голосові рушії все одно потребують
  64-бітних пристроїв із достатньою RAM.
- **compileSdk / targetSdk 35.** Перед публікацією підняти до вимог Google Play на той момент (якщо
  поширення буде через Play; для прямого APK це не обов'язково).
- `deleteSurroundingTextInCodePoints` (API 24+) не використовується: межі символів рахуються за графемами
  (емодзі з ZWJ, прапори, комбіновані знаки), що точніше за кодові точки.

## 3. Можливості `InputConnection` у сторонніх застосунках

| Операція | API | Де працює | Запасний варіант у коді |
|---|---|---|---|
| Вставити текст | `commitText` | усі текстові поля | для полів `TYPE_NULL` (термінали) — `sendKeyChar` |
| Видалити символ | `getTextBeforeCursor` + `deleteSurroundingText` | `EditText`, WebView, Compose | якщо текст недоступний — подія `KEYCODE_DEL` (видаляє «чипи» у месенджерах) |
| Виділений текст | `getSelectedText` | `EditText`, WebView | — |
| Рух курсора ←/→/Home/End | `getExtractedText` + `setSelection` | `EditText`, Compose `TextField` | `getExtractedText` часто `null` у WebView та власних редакторах → `KEYCODE_DPAD_*`, `KEYCODE_MOVE_HOME/END` |
| ↑/↓, PgUp/PgDn | лише події клавіш | залежить від застосунку | — (переміщення по рядках знає тільки поле) |
| Cut/Copy/Paste/Select all | `performContextMenuAction` | `TextView`, Chromium | Ctrl+X/C/V/A подіями клавіш |
| Undo/Redo | події Ctrl+Z / Ctrl+Shift+Z | `TextView` (API 24+) | у багатьох застосунках не підтримується — задокументовано |
| Enter | `performEditorAction` / `commitText("\n")` / `KEYCODE_ENTER` | згідно з `imeOptions` і багаторядковістю | Shift+Enter — завжди новий рядок у багаторядковому полі |
| Tab | `commitText("\t")` у багаторядкових, інакше `KEYCODE_TAB` | перехід фокусу в нативних і веб-формах | — |
| F1–F12, Esc, Ins, Ctrl/Alt-комбінації | `sendKeyEvent` | лише застосунки, що обробляють апаратні клавіші | — |
| Заміна сегмента (для перекладу) | `setComposingText` / `finishComposingText` | більшість полів | етап 9: підтвердження вставки вручну |

Висновок: базове введення та редагування надійні; функціональні клавіші й комбінації — «як на фізичній
клавіатурі», тобто залежать від застосунку. Це відображено в [KEY_SUPPORT.md](KEY_SUPPORT.md).

## 7. План суворої офлайн-дистрибуції

1. У маніфесті `INTERNET` і `ACCESS_NETWORK_STATE` видаляються (`tools:node="remove"`), навіть якщо їх
   додасть бібліотека. CI зупиняє збірку, якщо дозвіл потрапив у APK.
2. Хмарне резервне копіювання й перенесення даних вимкнені (`allowBackup=false`, `data_extraction_rules`).
3. Моделі: або вбудовані в APK (asset pack у межах розміру), або окремий локальний пакет (`.zip`),
   який імпортується через системний вибір файлу (Storage Access Framework) і розпаковується в приватну
   пам'ять застосунку. Завантаження з інтернету не передбачене.
4. Фінальна перевірка: встановлення на телефон, режим польоту, перезавантаження, повна перевірка
   функцій (див. [TESTING.md](TESTING.md)).

## 8. Відомі обмеження на цей момент

- Немає словника → немає підказок слів і автокорекції (етап 3 частково). Потрібен офлайн-словник
  з відповідною ліцензією для кожної мови.
- Доступність (TalkBack) по окремих клавішах не реалізована; уся клавіатура — один View.
- Немає власної теми/кольорів, лише світла й темна системні.
